OpenMeeting 服务端部署说明

从环境准备到服务启动，以步骤完成配置与记录。

Ubuntu x86_64Docker + Mage部署 IP · 203.0.113.10

一键设置部署 IP

应用后将同步更新全文地址与所有命令；点击“复制命令”即可复制更新后的内容。

当前使用示例 IP，请在执行命令前修改。

适用范围：Ubuntu x86_64 单机部署，Docker 运行依赖组件，Mage 启动业务微服务。

以下 Linux 命令在服务器 Bash 中执行；注明“本地 PowerShell”的命令在 Windows 执行。

首次部署按第一步至第七步执行，第八步填写验证记录。已有服务升级前先备份并核对版本，不重新覆盖 Compose、数据库或现有密钥配置。

复制使用：点击命令块右上角的“复制命令”，复制该段完整内容；多行配置的 EOF 结束符会一起复制。执行前替换示例地址、账号及密钥路径。复制按钮不会执行命令。

01一、部署前确认

1. 文档中的部署 IP 为 203.0.113.10。默认值仅作示例；请通过上方输入框设置服务器真实公网 IPv4 地址后再执行命令。

2. 使用云镜像配置的实际登录账号和对应 SSH 密钥。以下以 ubuntu 为示例，密钥路径 C:\Keys\example-key.pem 也需替换；是否允许 root 登录由服务器 SSH 策略决定。

本地 PowerShell：

PowerShell · 本地电脑
ssh -i "C:\Keys\example-key.pem" ubuntu@203.0.113.10

3. 项目路径以实际部署用户为准。下文默认使用该用户主目录下的 openmeeting-server；已有部署应改为实际目录。

下文使用：

Bash · 服务器
export SERVER_IP="203.0.113.10"
export APP_DIR="$HOME/openmeeting-server"

4. 当前仓库要求 Go >= 1.21.2。本文以 Go 1.21.6 作为示例构建基线，不代表最新或长期维护推荐版本。

5. 主持人移交修复分两部分：

- OpenMeeting 服务端：至少包含 ae64a2ba1e86fd71476311f76290df122163d57c。

进行中会议按当前主持人归属；预约和历史会议仍按创建人归属。

- Cohavora 客户端：另行部署包含主持人业务 API、白板权限、参会人列表、结束会议状态同步及提示自动消失修复的版本。

更新 OpenMeeting 服务端不会自动更新客户端。

6. 先完成网络和凭据配置，再对外启用服务。示例沿用仓库初始化凭据；首次部署前应在数据库、Redis、LiveKit 和业务配置中成套替换，并保持一致。

已有部署修改数据库环境变量不会自动修改数据库内的现有密码，须按对应组件的改密流程处理。

02二、可选：GitHub 访问加速

仅在服务器无法正常访问 GitHub 时使用。确认本地访问github正常且代理端口确实支持 SOCKS5。

本地 PowerShell（另开终端并保持连接）：

PowerShell · 本地电脑
ssh -i "C:\Keys\example-key.pem" -R 7890:127.0.0.1:7890 ubuntu@203.0.113.10

该 SSH 会话中的服务器 Bash：

Bash · 服务器
export http_proxy=socks5h://127.0.0.1:7890
export https_proxy=socks5h://127.0.0.1:7890

用完后：

Bash · 服务器
unset http_proxy https_proxy ALL_PROXY all_proxy

SSH 主机指纹变化时先核实服务器身份，不应直接删除 known_hosts 记录。

源码获取是必做步骤，见第三步；本节仅提供可选代理方法。

03第一步：安装 Docker 与 Compose 插件（首次部署）

已有 Docker 环境先检查 docker version、docker compose version，满足要求时跳过安装。

以下 apt、/etc 与 systemctl 命令需要管理员权限；具备 sudo 权限的部署用户可先 sudo -i，执行完系统安装后 exit 回原用户。

不要在 root 会话中无意把后续项目部署到 /root。

采用清华镜像源；若镜像不可达，以实际网络条件调整。安装前清除临时代理：

Bash · 服务器
unset http_proxy https_proxy ALL_PROXY all_proxy
Bash · 服务器
# 1. 基础工具与 Keyrings 目录创建
apt update -y && apt install -y curl ca-certificates git wget
install -m 0755 -d /etc/apt/keyrings
curl -fsSL "https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/ubuntu/gpg" -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
Bash · 服务器
# 2. 写入清华软件源（自动匹配系统版本代号）
CODENAME=$(. /etc/os-release && echo "$VERSION_CODENAME")
cat <<EOF > /etc/apt/sources.list.d/docker.list
deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/ubuntu ${CODENAME} stable
EOF
Bash · 服务器
# 3. 安装 Docker 组件并启动
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker

04第二步：可选配置 Docker 镜像加速源

仅在拉取镜像受阻时配置。镜像站可能不可用，以下列表不保证持续有效；Docker Hub 镜像加速也不一定覆盖 quay.io。

已有 /etc/docker/daemon.json 时先备份并合并 registry-mirrors，不要直接覆盖其他配置。

以下为新环境的示例；重启 Docker 可能影响已有容器，需安排维护窗口。

Bash · 服务器
mkdir -p /etc/docker
cat <<EOF > /etc/docker/daemon.json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net",
    "https://docker.1panel.live",
    "https://hub-mirror.c.163.com"
  ]
}
EOF
Bash · 服务器
systemctl daemon-reload && systemctl restart docker

05第三步：拉取源码与调整 LiveKit 为 Host 网络模式

说明：本文采用 LiveKit host 网络方案，减少容器端口映射配置。host 网络不是所有部署的强制要求，也不能保证没有丢包。

以下操作回到部署用户执行；该用户需具备 Docker 使用权限，权限不足时按本机权限策略使用 sudo docker。

Bash · 服务器
# 1. 获取源码（首次部署必做；目录已存在时不要重复 clone，先备份并按已有部署的升级流程处理）
export APP_DIR="$HOME/openmeeting-server"
git clone https://github.com/a980374208/openmeeting-server.git "$APP_DIR"
cd "$APP_DIR"
Bash · 服务器
# 核对当前版本和主持人修复；任一失败时停止，不应继续宣称修复已部署
git log -1 --oneline
git merge-base --is-ancestor ae64a2ba1e86fd71476311f76290df122163d57c HEAD
# 上一命令退出码为 0 表示 HEAD 包含该提交，1 表示不包含，其他值表示检查失败。
Bash · 服务器
# 原仓库 .env 需保留；检查其中镜像、DATA_DIR、DOCKER_DIR 与实际挂载一致。
# 为可复现部署，记录镜像 tag 和 digest；不要将 latest 视为固定版本。
Bash · 服务器
# 2. 将 docker-compose.yml 中的 livekit 调整为 host 网络模式
cat <<'EOF' > docker-compose.yml
version: '3.8'

networks:
  openmeeting:
    driver: bridge

services:
  mongodb:
    image: "${MONGO_IMAGE}"
    ports:
      - "37017:27017"
    container_name: mongo
    command: [ "/bin/bash", "-c", "/docker-entrypoint-initdb.d/mongo-init.sh; docker-entrypoint.sh mongod --wiredTigerCacheSizeGB 1 --auth" ]
    volumes:
      - "${DATA_DIR}/mongodb/data/db:/data/db"
      - "${DATA_DIR}/mongodb/data/logs:/data/logs"
      - "${DATA_DIR}/mongodb/data/conf:/etc/mongo"
      - "./scripts/mongo-init.sh:/docker-entrypoint-initdb.d/mongo-init.sh:ro"
    environment:
      - TZ=Asia/Shanghai
      - wiredTigerCacheSizeGB=1
      - MONGO_INITDB_ROOT_USERNAME=root
      - MONGO_INITDB_ROOT_PASSWORD=openMeeting123
      - MONGO_INITDB_DATABASE=openmeeting_v1
      - MONGO_OPENIM_USERNAME=openmeeting
      - MONGO_OPENIM_PASSWORD=openMeeting123
    restart: always
    networks:
      - openmeeting

  redis:
    image: "${REDIS_IMAGE}"
    container_name: redis
    ports:
      - "16379:6379"
    volumes:
      - "${DATA_DIR}/redis/data:/data"
      - "${DATA_DIR}/redis/config/redis.conf:${DOCKER_DIR}/redis/config/redis.conf"
    environment:
      TZ: Asia/Shanghai
    restart: always
    sysctls:
      net.core.somaxconn: 1024
    command: redis-server ${DOCKER_DIR}/redis/config/redis.conf --requirepass openmeeting_v1 --appendonly yes
    networks:
      - openmeeting

  etcd:
    image: "${ETCD_IMAGE}"
    container_name: etcd
    ports:
      - "12379:2379"
      - "12380:2380"
    environment:
      - ETCD_NAME=s1
      - ETCD_DATA_DIR=/etcd-data
      - ETCD_LISTEN_CLIENT_URLS=http://0.0.0.0:2379
      - ETCD_ADVERTISE_CLIENT_URLS=http://0.0.0.0:2379
      - ETCD_LISTEN_PEER_URLS=http://0.0.0.0:2380
      - ETCD_INITIAL_ADVERTISE_PEER_URLS=http://0.0.0.0:2380
      - ETCD_INITIAL_CLUSTER=s1=http://0.0.0.0:2380
      - ETCD_INITIAL_CLUSTER_TOKEN=tkn
      - ETCD_INITIAL_CLUSTER_STATE=new
    restart: always
    networks:
      - openmeeting

  livekit:
    image: "${LIVEKIT_IMAGE}"
    container_name: livekit
    network_mode: host
    volumes:
      - ${DATA_DIR}/livekit/config/livekit.yml:${DOCKER_DIR}/livekit.yaml
    environment:
      TZ: Asia/Shanghai
    restart: always
    command: --config ${DOCKER_DIR}/livekit.yaml --bind 0.0.0.0
    depends_on:
      - redis
EOF

06第四步：配置 LiveKit 与业务服务公网 IP（单端口生产模式）

Bash · 服务器
export SERVER_IP="203.0.113.10"
cd "$APP_DIR"
mkdir -p components/livekit/config
Bash · 服务器
# 1. 配置 LiveKit SFU 核心配置（固定单端口 17882/udp，移除随机范围端口）
cat <<EOF > components/livekit/config/livekit.yml
port: 17880
log_level: info
rtc:
  tcp_port: 17881
  use_external_ip: false
  node_ip: ${SERVER_IP}
  udp_port: 17882

keys:
  APIftrpEkL9x2pa: 23ztfSqsfQ8hKkHzHTl3Z4bvaxro0snjk5jwbp5p6Q3
room:
  empty_timeout: 72000
  departure_timeout: 86400
EOF
Bash · 服务器
# 2. 配置业务服务连接 LiveKit 的 WebSocket 地址
# 下条 sed 仅用于含 external_ip 占位符的新配置。已有配置应核对 url，不能仅重复执行替换命令。
# config/livekit.yml 的 url 应指向 ws://${SERVER_IP}:17880；两侧 API key/secret 必须匹配。
sed -i "s/external_ip/${SERVER_IP}/g" config/livekit.yml
Bash · 服务器
# 3. 配置 UDP 缓冲区（需管理员权限；已有更高数值时保留原调优值）
# 以下值沿用本部署基线，不代表媒体质量保证；同时检查其他 sysctl 文件有无重复配置。
sudo tee /etc/sysctl.d/90-openmeeting-udp.conf >/dev/null <<'EOF'
net.core.rmem_max=5000000
net.core.wmem_max=5000000
EOF
sudo sysctl --system
Bash · 服务器
# 4. 启动容器依赖组件（MongoDB、Redis、Etcd、LiveKit）
docker compose up -d
Bash · 服务器
# 5. 检查启动状态和错误日志；Up 仅表示容器运行，不代表业务或媒体验证通过
docker compose ps
docker compose logs --tail=80 livekit
# 日志可能包含敏感配置，分享前先脱敏。

09第七步：安全组与主机防火墙（保留原说明全部放行端口）

以下清单包含原部署说明中的全部端口。云安全组与主机防火墙均需配置对应规则。

放行规则本身不会启动服务；端口用途及是否实际监听，以部署配置为准。

本文基础配置未部署 Nginx、TLS 或 TURN，扩展端口仍保留在完整清单中。

协议端口用途与放行范围
TCP22SSH 登录及 SSH 端口转发；允许维护来源 IP。
TCP80HTTP 反向代理及证书 HTTP 校验；公网访问时允许 0.0.0.0/0。
TCP443HTTPS / 安全 WebSocket 反向代理入口；公网访问时允许 0.0.0.0/0。
TCP11020原说明保留的客户端业务扩展端口；具体服务按实际配置核对，当前默认客户端 API 为 11102。
TCP11022openmeeting-admin-api 管理接口；允许管理来源或内网。
TCP11102openmeeting-api：客户端注册、登录、会议业务接口；按客户端访问范围放行。
TCP17880LiveKit HTTP / WebSocket 信令；按客户端访问范围放行。
TCP17881LiveKit TCP ICE 回退；按客户端访问范围放行。
TCP5349TURN TLS 扩展端口；实际启用 TURN TLS 后使用。
TCP8080原说明保留的 Web / 管理页面扩展端口；按实际监听服务及访问范围配置。
TCP8443原说明保留的 HTTPS / 管理页面扩展端口；按实际监听服务及访问范围配置。
UDP17882LiveKit 单端口媒体通道；按客户端访问范围放行。
UDP3478STUN / TURN 扩展端口；实际启用对应服务后使用。
UDP50000-60000原说明保留的媒体 / TURN 中继端口范围；实际用途和范围按对应组件配置核对。

安全组批量录入参考（端口全部保留，访问来源按上表设置）：

TCP：22、80、443、11020、11022、11102、17880、17881、5349、8080、8443。

UDP：17882、3478、50000-60000。

若控制台不支持逗号分隔的多端口输入，按单端口分别建规则；范围端口按控制台要求填写。

IPv6 放行：

使用 IPv6 时，另建 IPv6 入站规则，并确认服务监听 IPv6、服务器具备 IPv6 地址和路由。

原说明中的 IPv6 清单保留如下：

TCP：11020、11022、17880、17881。

UDP：17882、3478。

客户端 API 11102 及其他上表端口如也提供 IPv6 访问，补充对应 IPv6 规则。

公网 IPv6 来源可使用 ::/0；维护和管理端口按实际来源限制。

仅配置 IPv4 的部署不需要额外启用 IPv6。

配置说明：

- 本文 rtc.udp_port=17882 使用单端口媒体模式；保留 UDP 50000-60000 规则不代表 LiveKit 会自动使用该范围。

- 放行 UDP 3478 / TCP 5349 不等于已启用 TURN；还需配置监听、地址及相应证书等服务参数。

- 80、443、11020、8080、8443 是否有服务监听，应结合实际部署核对。

内部依赖端口（与上述原说明公网放行清单分开）：

MongoDB 37017、Redis 16379、etcd 12379/12380；

RPC 11110/11112；指标 21100/21101/21113/20114。

这些端口用于内部组件通信或监控，不因补齐原清单而新增公网开放要求。

Compose 中 ports 映射可能监听所有网卡，应由绑定地址与防火墙落实访问范围。
