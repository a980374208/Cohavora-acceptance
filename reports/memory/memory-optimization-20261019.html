实际修改与根因

工具：注册前目标检查与实际注册共用异常分支，导致未派发也被报为注册结果不明；早期异常还缺少安全终态。现以 schema 2 分别记录注册和建会的 NOT_SENT / SENT_UNKNOWN / CONFIRMED；仅真正派发前落 REGISTRATION_REQUESTED。本地身份准备为 IDENTITY_PREPARED。只允许固定阶段、错误码、异常类型和数字 errno/winerror，避免原始异常、响应体、账号密码和 token 进入回执。安全私有目录建立且持有 lease 后才尽力写终态；没有安全输出目录、resume 未验证或 lease 忙时明确报告无法安全持久化，不寻找其他目录、不改旧 ACL。建会保留底层安全阶段；不确定结果恢复仍须经确认的 meeting ID。注册最多一次，resume 永不注册。

外层单次包装归并到维护源，复用原 host/target/run 配置、guardian 和 retained process identity，未复制另一套编号执行框架。显式绑定冻结 SID/session、解释器和父计划哈希；授权校验后 CreateNew 单次消费，失败不重试；能力回执从冻结 manifest 解析，按保留句柄进行有界等待和 owned cleanup。修正跨部署根竞争检查、Windows PowerShell 5.1 的模块路径干扰、isolated Python 相邻模块导入，以及依赖 Python 3.11 file_digest 的兼容问题。

产品：导出逐行 JSON 树与 CSV 转义临时对象带来可避免的请求分配；现在复用已有 JSON 编码助手和缓冲。日志重复保留三份派生 QString，隐藏时仍投影 document/status；现在按需格式化并推迟投影。独立审查还发现隐藏全文复制后再切回旧主题会使记忆 palette 与实际文档不同步，已在全文复制投影前同步主题，并新增精确颜色回归。面板原在 BuildFrame 后整份复制以调整内存展示，现由私有 builder 在发布前调整，公开/已发布对象仍 immutable。

保留日志 pending 2048 条/2 MiB、cache 5000 条/8 MiB、原 document cap，以及 drain 128 条/2 ms、render 128 条/4 ms。状态标签仅在文本实际变化时 setText；这不构成对 UIA 事件次数的判断。队列倍率与缓存预算不变，未删除指标、降低采样、跳过导出或改变产品负载。

内存计费修正

原 sizeof(SafeTelemetryRecord) + SnapshotRetainedBytes 重复计算嵌入 Snapshot 固定空间；拆分动态估算后，每条扣除本 ABI 的 sizeof(Snapshot)=8320，再计匿名 ID capacity+1（本夹具为 48）。plain 为 21,408 → 13,136 字节，fine 为 37,424 → 29,152 字节；独立旧公式 oracle 与实际 store status 相符。全部既有字符串/容器容量仍计入，SSO capacity 仍保守计费，不猜标准库内部布局。

这是计费准确性修复，不是实际内存下降。8 MiB cap 与队列安全限额未降；修正后可能保留更多 live records，使真实内存增加。没有利用账目变化宣称产品预算或 B14 PASS。
